# Contributing to Elmahrosa AI App Store Builder

Thank you for your interest in contributing to our project! We welcome contributions from the community to help make this platform better.

## 📋 How to Contribute

There are many ways to contribute to Elmahrosa AI App Store Builder:

1. **Report bugs** - Use the issue template to report bugs
2. **Suggest features** - Share your ideas for new features or improvements
3. **Improve documentation** - Help us make our docs clearer and more complete
4. **Fix issues** - Pick up an issue marked as "good first issue" or "help wanted"
5. **Add new features** - Implement new functionality following our guidelines

## 🐛 Reporting Bugs

Before reporting a bug, please check if it has already been reported by searching the [Issues](https://github.com/Elmahrosa/elmahrosa-ai-app-store-builder/issues).

When reporting a bug, please include:
- A clear and descriptive title
- Steps to reproduce the issue
- Expected behavior vs. actual behavior
- Screenshots or screen recordings if applicable
- Your environment (OS, browser version, etc.)

Use the "Bug Report" issue template when creating a new issue.

## 💡 Suggesting Features

We love hearing your ideas for new features! When suggesting a feature, please consider:
- How does this align with our project goals?
- Who would benefit from this feature?
- Are there any privacy or security considerations?

Use the "Feature Request" issue template when creating a new issue.

## 🛠️ Development Workflow

### Setting Up Your Environment

1. Fork the repository to your GitHub account
2. Clone your fork locally:
   ```bash
   git clone https://github.com/your-username/elmahrosa-ai-app-store-builder.git
   ```
3. Create a branch for your work:
   ```bash
   git checkout -b feature/your-feature-name
   ```
4. Set up your development environment following the [Getting Started](#-getting-started) guide

### Making Changes

1. Follow our coding standards (see below)
2. Write tests for new functionality
3. Ensure all tests pass
4. Update documentation as needed
5. Commit your changes with clear, descriptive messages

### Submitting Changes

1. Push your branch to your fork:
   ```bash
   git push origin feature/your-feature-name
   ```
2. Open a pull request against the `main` branch of the upstream repository
3. Fill out the pull request template completely
4. Respond to any feedback from maintainers

## 📝 Coding Standards

### JavaScript/TypeScript
- Follow [Airbnb JavaScript Style Guide](https://github.com/airbnb/javascript) with TypeScript extensions
- Use ESLint and Prettier for code formatting
- Meaningful variable and function names
- Comment complex logic, but aim for self-documenting code

### Python
- Follow [PEP 8](https://pep8.org/) and [PEP 257](https://pep257.readthedocs.io/)
- Use descriptive names and docstrings
- Keep functions focused and small
- Use type hints where beneficial

### Kotlin/Android
- Follow [Kotlin Coding Conventions](https://kotlinlang.org/docs/coding-conventions.html)
- Use meaningful names and comments
- Follow Android Architecture Components guidelines
- Write unit tests for business logic

### General
- Keep dependencies up to date
- Write tests for new code
- Update documentation when changing functionality
- Follow the principle of least privilege for permissions

## 🧪 Testing

- Write unit tests for all new business logic
- Ensure new features have adequate test coverage
- Run the full test suite before submitting a PR
- Include both positive and negative test cases
- Mock external dependencies in unit tests

## 📚 Documentation

- Update README.md if changing project structure or setup
- Add JSDoc/TsDoc comments for public APIs
- Update inline documentation when changing functionality
- Create or update architectural decision records for significant changes
